# Checklist de levantamiento técnico-funcional

Marca cada rubro cuando tengas **evidencia** (no solo dicho por alguien).

## Funcional
- [ ] Objetivo del sistema documentado
- [ ] Usuarios/roles identificados
- [ ] Procesos de negocio mapeados
- [ ] Reglas de negocio extraídas del código y validadas con negocio
- [ ] Casos de excepción documentados

## Técnico
- [ ] Inventario de componentes (app, API, BD, batch, integraciones)
- [ ] Arquitectura diagramada (contexto + contenedores)
- [ ] Endpoints documentados (método, parámetros, request, response, errores)
- [ ] Tablas documentadas (estructura, relaciones, campos críticos)
- [ ] Jobs/batch documentados (horario, entrada, salida, dependencias, RC)
- [ ] Flujos de información trazados de punta a punta

## Operativo
- [ ] Incidentes históricos analizados y clasificados
- [ ] Runbooks para los incidentes más frecuentes
- [ ] Códigos de retorno/error documentados
- [ ] Riesgos operativos identificados (doble corrida, archivo faltante, token)

## Conocimiento
- [ ] Single Points of Knowledge identificados (¿quién es el "Ricardo"?)
- [ ] Conocimiento crítico transferido a documentos
- [ ] Preguntas pendientes registradas con dueño
- [ ] Todo documento validado por el responsable técnico correspondiente
